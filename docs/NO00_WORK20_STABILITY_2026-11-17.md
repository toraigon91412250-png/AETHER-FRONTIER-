# AETHER FRONTIER｜No.00 統合受け入れ準備・安定化パス

作成日：2026-11-17／担当：No.00

## 作業の理由
Work20統合試作は `playtest/work20/` に独立し、従来のルート `index.html` を保護する。現在は `aether-frontier-work20-v1` キーに主要進行と遺構・荒野を保存するが、No.04神殿、No.05研究施設、No.06工場の途中状態は保存していなかった。また、これらの原版モジュールは `getState()` はあるが `setState()` がない。

## 修正内容
- No.00側の `module-progress.js` によって `moduleStates.version=1` を追加保存。既存の保存キーと既存フィールドは変更しない。
- 元ソースを改変せずに、各モジュールの公開された `interact()` と `getState()` を利用して進行を再現する。ゲートやライトの見た目を伴う操作も再現する。
- いずれかのエリアの状態が不正でも、そのエリアの復元エラーを隔離して他エリアを続行。不要な操作・未知の装置ID・品質設定・未来の保存形式は無視。
- 将来 `setState()` をネイティブ実装したチームでは、公開APIを優先する。
- 保存を操作成功時だけでなく、アプリを中断・非表示にした際にも更新する。ユーザーが未保存の進行を失いにくくする。
- リセット時に新セーブを空の初期状態で上書きし、旧セーブの自動再インポートを防ぐ。リセット直後の画面遷移では自動保存を抑制。旧キーは削除しない。
- 完成済みの闘技場座標修正・移動テストを維持する。
- No.00納品受け入れツール `tools/aether-intake.py` を追加。ZIPを解凍・実行せずにパス、重複、シンボリックリンク、暗号化、ZIPボム条件、CRC、ソースとHTML、README、SHA256をチェック。

## 互換性
- `main/index.html` は変更しない。Work20専用の小規模パッチ。
- `teams/01..20` 原版、`integration/` の共通アダプターは変更しない。
- 従来の `aether-frontier-work20-v1` のセーブはそのまま読み込める。`moduleStates` フィールドのない旧セーブも有効。
- セーブの戻し先はパズルや機械設備の**進行状態**。プレイヤー位置まで正確に再開する仕様は今回は追加しない。
- No.07荒野、遺構、ボス撃破の旧セーブ方式は維持する。

## 20チームの更新が届いたときのルール
1. ファイルは `incoming/noNN/<日付>/` といった隔離領域に原版保持。チームのファイル名とSHA256を記録。
2. 上記ZIP受け入れツールでスキャン（これだけでは悪意あるコードを検出できない）。
3. 公開API・ファイル構成・保存状態の旧版との差を比較。
4. 単体HTMLの動作、Nodeテスト、PCブラウザ、iPhone Safariで段階確認。
5. 統合側アダプターで吸収可能なら原版は保護。`main` に一括上書きしない。
6. 必ず差分・ロールバック手順・未解決バグを記録してから統合。
